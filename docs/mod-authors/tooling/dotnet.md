# C# generators and patchers

Build executable C# projects with their own NuGet references and a matching .NET
SDK.

## `@addon/bmk/dotnet`

```lua
target("MainPlugin")
    set_default(false)
    add_extrafiles("src/mutagen/MainPlugin/FormIDs.txt")
    add_rules("@addon/bmk/dotnet", {
        project = "src/mutagen/MainPlugin/MainPlugin.csproj",
        arguments = {"$(outputdir)/MyMod.esp", path.absolute("src/mutagen/MainPlugin/FormIDs.txt")},
        outputs = {"MyMod.esp", "Strings/**"}
    })
```

| Option          | Default   | Purpose                                                                                         |
| --------------- | --------- | ----------------------------------------------------------------------------------------------- |
| `project`       | Required  | Path to the executable C# project.                                                              |
| `arguments`     | `{}`      | Arguments passed to the generator. `$(outputdir)` expands to the directory for generated files. |
| `outputs`       | `{}`      | Generated files to include when packaging this target.                                          |
| `configuration` | `Release` | MSBuild configuration.                                                                          |

BMK invokes MSBuild before running the generator. C# binaries and intermediates
go under `build/intermediates/dotnet/<target>/`. Generated game files go under
`build/artifacts/<target>/`, or the target's `set_targetdir`.

Declare external generator inputs with `add_extrafiles`. Built assemblies,
program arguments and those inputs determine whether the generator runs again.

### Persistent FormIDs

FormID allocation belongs to the C# generator. Mutagen's
[`TextFileFormKeyAllocator`](https://mutagen-modding.github.io/Mutagen/plugins/FormKey-Allocation-and-Persistence/)
persists IDs by allocation name. Supply a unique, stable name when creating each
record:

```csharp
var quest = mod.Quests.AddNew("MyMod_Quest");
```

Setting `EditorID` after calling parameterless `AddNew()` does not enable
persistence. Allocation names are case-sensitive. Changing one allocates a new
ID.

Use one mapping file per plugin and commit it with the generator. Keep entries
for released records, including records omitted from a later build. Variants of
the same plugin can share a mapping when generated sequentially. Save the
allocation map after writing the plugin outputs.

## Skyrim MCM quests

Add `BethesdaModKit.Mutagen` to a Skyrim generator that creates an MCM Helper
quest:

```xml
<PackageReference Include="BethesdaModKit.Mutagen" Version="0.1.0" />
```

Create the quest after installing the generator's persistent FormID allocator:

```csharp
using BMK.Mutagen.Skyrim;

var quest = McmQuest.Add(
    mod,
    new McmQuestOptions
    {
        EditorId = "MyMod_MCMQuest",
        DisplayName = "My Mod",
        ConfigScriptName = "MyMod_MCM",
        ModName = "MyMod",
    }
);
```

`EditorId` is the allocator's stable record name. The helper attaches the
configured script and SkyUI player-load alias. `ModName` sets the menu's display
name. MCM Helper derives its settings identifier from the quest's plugin. The
method returns the created quest.

## Synthesis rules

`@addon/bmk/skyrim.synthesis` and `@addon/bmk/fallout4.synthesis` build and run
Synthesis patchers through the
[`run-patcher` CLI](https://mutagen-modding.github.io/Synthesis/devs/Patcher-CLI/).

Set `data` to the directory containing the plugins your patcher needs and
`load_order` to the file listing their load order:

```lua
target("OtherModPatch")
    set_default(false)
    add_rules("@addon/bmk/skyrim.synthesis", {
        project = "src/synthesis/OtherModPatch/OtherModPatch.csproj",
        data = "C:/PatchInputs/Data",
        load_order = "patch-loadorder.txt",
        output = "MyMod-OtherMod.esp"
    })
```

| Option          | Default                      | Purpose                                                  |
| --------------- | ---------------------------- | -------------------------------------------------------- |
| `project`       | Required                     | Path to the Synthesis C# project.                        |
| `data`          | Staged from `add_extrafiles` | Directory containing input plugins and associated files. |
| `load_order`    | Required                     | Path to the input load-order file.                       |
| `output`        | Required                     | Output plugin filename.                                  |
| `arguments`     | `{}`                         | Additional `run-patcher` arguments.                      |
| `configuration` | `Release`                    | MSBuild configuration.                                   |

The patcher writes its output plugin to `build/artifacts/<target>/`, or the
target's `set_targetdir`.

Your patch may need both a plugin generated by this project and another mod's
plugin. If they live in different directories, omit `data` and select the files
with `add_extrafiles`. For example, a patch for your generated `MyMod.esp` and
`OtherMod.esp`:

```lua
target("OtherModPatch")
    add_deps("MainPlugin", {inherit = false})
    add_extrafiles("$(builddir)/artifacts/MainPlugin/MyMod.esp")
    add_extrafiles("dependencies/OtherMod.esp")
```

BMK copies those files into a temporary Data directory for Synthesis. Include
the masters and associated files the patcher needs, and provide `load_order` as
above. `add_deps` builds your plugin before running the patcher. It does not
include that plugin in the patch package.

Select the patcher target in the package:

```lua
target("Compatibility")
    set_version("1.0.0")
    add_rules("@addon/bmk/skyrim.package", {targets = {"OtherModPatch"}})
```
